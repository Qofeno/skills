# Landing Page Playbook

Use this when the project is specifically a landing/marketing page (not a full app). Consult this alongside the design-token and component-library steps in `SKILL.md` — it doesn't replace them.

## Before designing: get the real inputs

Beyond what `SKILL.md` Step 1 already asks (purpose, mood, colors, framework), a landing page specifically needs:

- **The one action a visitor should take.** A landing page earns its keep on a single primary conversion goal — sign up, book a call, buy, download. If the user hasn't said what it is, ask. Multiple competing CTAs dilute conversion; know the *one* thing before laying out sections.
- **Who's actually landing there.** Cold traffic from an ad needs more context and trust-building than a visitor who already knows the brand from a referral. This changes how much explaining the page needs to do before asking for the click.
- **What objection is most likely to stop someone.** Price, trust, "will this actually work for me" — knowing the real objection shapes which section carries the most weight (a testimonials/social-proof section matters more when trust is the objection; a comparison section matters more when the objection is "why you over the alternative").

## Structure — order sections around the objection, not a template

A reasonable default order — but treat it as a starting point to adapt, not a fixed template to fill in on autopilot:

1. **Hero** — the core value proposition in one clear sentence, plus the primary CTA. A visitor should understand what this is and what to do within seconds, not after scrolling.
2. **Social proof or credibility signal** — only if real proof exists (see Content realism below). Skip this section entirely rather than fabricate it.
3. **How it works / core value** — the meat of the page, addressing the specific objection identified above.
4. **Detail/features section** — supporting points, not a burial ground for every possible feature. Prioritize what actually moves the primary objection.
5. **Final CTA** — repeat the primary action, often with a lower-friction framing (e.g. "start free" rather than "buy now") if that fits the funnel stage.

Not every landing page needs every section — a page for a known, trusted brand's simple signup might skip heavy objection-handling entirely and go hero → CTA. Match structure to the actual visitor and objection, don't pad the page to look "complete."

## Conversion copy — specific beats generic

- Headlines should state the actual outcome or value, not an abstract claim. "Ship your backend in an afternoon" beats "The future of backend development."
- CTA button text should say what happens next, not just "Submit" — "Start free trial," "Get my quote," "Book a demo."
- Avoid stacking adjectives without substance ("revolutionary," "game-changing," "seamless") — if a claim can't be backed by something concrete, cut the adjective and state the concrete thing instead.

## Content realism (ties to `SKILL.md`'s "No stand-ins" rule)

- Never invent specific numbers ("10,000+ users," "99.9% uptime") without the user confirming they're real. A vague-but-true claim beats a precise-but-fabricated one.
- Never invent testimonial names, quotes, or company logos. If the user has real ones, use them. If not, skip the section or mark it clearly as pending real content — don't placeholder it with "Jane D., CEO" and a stock quote.
- Avoid copy that reads as obviously AI-generated boilerplate — generic enthusiasm without specifics is a tell. Specific, concrete language tied to what the product actually does reads as real because it is.

## Visual execution notes

- Give the hero headline real typographic weight — it's the first thing read, and timid sizing undercuts the value proposition before anyone reads a word.
- Keep the primary CTA visually distinct from secondary actions (a filled button vs. a text link, not two equally-weighted buttons competing for attention).
- Respect the type scale and spacing system from `SKILL.md` Step 2 — a landing page is not an excuse for one-off font sizes per section.
